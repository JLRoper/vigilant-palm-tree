### 2026-08-01 01:35 (completed)
- Fixed multiplayer lobby smoke test (`test/multiplayer.smoke.ts`) which was failing
  with `AssertionError: lobby should have 2 seats` (actual: undefined).
- Root cause: `server/routes.ts` POST /games only built `lobbyState` when the request
  body included a `lobby` object, so bare `humanSlots: 2` left `lobbyState = {}` and
  the response's `lobby` column came back empty.
- Fix in `server/routes.ts` POST /games:
  - Accept bare top-level `humanSlots` (with or without a `lobby` object). Fall back
    to legacy `lobby.humanSlots` if top-level is absent.
  - When no explicit `lobby.seats` is provided, default `seats` to `initial.players.length`.
  - Also forward `humanSlots` into `makeInitialStatePayload` via `playerCount` and
    `humanSeatCount` so the generated game has the requested number of players
    (otherwise `initial.players.length` stays at the default 3 and `lobby.seats`
    comes back as 3 instead of the requested 2).
  - Kept existing validation: `seats >= 1`, `humanCount >= 1`, `humanCount <= seats`.
- Did not change `test/multiplayer.smoke.ts` (test was correct, server was wrong).
- Verification: `npm run build` passes (tsc + vite build clean).
