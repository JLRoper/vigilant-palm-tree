# Map

<!-- docs:verified 2026-10-17 -->

The world the heroes move through. Hex grid, isometric rendering, procedurally generated.

## Status

✅ **Implemented.** Procedural map generation, 9 terrain types, biome-aware resource placement, server-side tile persistence, isometric rendering, camera (pan/zoom, DPR-aware), fog of war, and minimap all ship in v1. Rivers ship as a map-gen **v5** overlay layer (see [Rivers](#rivers)).

## Grid

- **Configurable hex grid** (`MapSize`: `small` 24×18, `medium` 36×27, `large` 48×36, `huge` 72×54, `epic` 120×90, `colossal` 180×135, `titanic` 240×180, `gigantic` 300×225; default `small` 24×18), axial coordinates `(q, r)`. The ladder lives in `MAP_SIZE_ORDER`/`MAP_SIZES` (`packages/engine/src/map/gameMap.ts`) and every size selector iterates it, so a new tier is one registry entry.
- Hex size = 32 logical px.
- Pointy-top orientation, flat-top stack.
- `GameMap.placedResourceTiles` caches the sparse array of placed resource deposits alongside the indexed `resourceTiles` lookup array, and `getOrCreateGameMap(seed, size)` (`packages/engine/src/map/gameMap.ts`) maintains a process-wide LRU cache (`GAME_MAP_CACHE_CAPACITY = 32`) of generated `GameMap` instances keyed by `(seed, size, mapGenVersion)`.

## Terrain types

| Terrain | Fill | Move cost | Notes |
|---------|------|-----------|-------|
| Grass   | green       | 1         | Default. Plains — most common terrain. |
| Dirt    | brown       | 1         | Roads / paths. Exposed, barren ground — proxy for arid land in v1. |
| Forest  | dark green  | 1.2       | Slow, decorative trees. Wood-bearing biome. |
| Dense forest | near-black green | impassable | Rarer thicket that grows against the forest edge. Never walkable, never carries a deposit. Its neighbours are rewarded — see below. |
| Desert  | sand yellow | 1.4       | Passable but harsh. Arcane-bearing biome (ancient ruins). |
| Swamp   | murky olive | 2         | Waterlogged bog. Slow going (2× a normal tile). |
| Snow    | pale blue-white | 2     | Frozen ground. Slow going (2× a normal tile). |
| Mountain| grey rock   | impassable| Peaks and ridges. Stone + iron-bearing biome. Lakes / rivers. |
| Water   | blue        | impassable| Lakes / rivers. Never carries resources. |

Generated via a deterministic biome-blob growth pass (`generateTerrain`, using a deduplicated `Uint8Array(w * h)` frontier bitset, O(1) swap-and-pop removal, and `scaledTerrainBlobs` scaling biome blob counts by $\sqrt{N/432}$ for maps larger than `24×18`) on the map seed. Same seed → same map. **Dense forest is a map-gen v4 feature** (`DENSE_FOREST_FRACTION = 0.06` against forest's `0.15`): it is grown last, seeded on a non-forest neighbour of a forest tile and biased to expand from tiles that still touch forest, so it usually borders the forest it grew out of while its own rim still meets the surrounding biome. v1–v3 maps are unchanged — v4 only *adds* dense forest, never overwrites forest, so a saved v3 game keeps its exact terrain. Implementation: [`packages/engine/src/map/gameMap.ts`](../packages/engine/src/map/gameMap.ts), [`packages/engine/src/map/terrain.ts`](../packages/engine/src/map/terrain.ts). See [map-gen.md](./map-gen.md) for the algorithm.

## Rivers (map-gen v5, overlay layer)

Rivers are **not a terrain value**: they are an overlay layer (`RiverTile[]` on `GameMap`, sparse-indexed via `GameMap.riverAt`) that runs across the existing biome, so a river tile keeps its biome underneath (grass/forest/desert…) with blue water drawn on top. Two kinds:

| Kind | Crossing | Notes |
|------|----------|-------|
| Small | Costs a full day (7 movement points — the whole round budget) | No bridge; the hero must end the turn on the far bank |
| Wide | Impassable except at bridges | Bridges are baked at generation (~every 8 cells, at least one per river, never within two cells of the mouth); a bridge crossing costs 1 |
| Any | — | A river cell at either end of the channel renders as a pass-through to its adjacent body of water, so the river visibly pours into the lake/swamp rather than stubbing out one tile short of it |

- Generated by `placeRivers` (`packages/engine/src/map/rivers.ts`) after every terrain pass, so v1–v4 grids are byte-identical for the same seed; rivers exist only on maps generated at map-gen **v5** (`CURRENT_MAP_GEN_VERSION`).
- A river runs from one body of water to another — water **and swamp** cells both count as bodies.
- The walk is A*-guided with a momentum term: it descends a distance-to-sink field, forbids U-turns, charges soft turns 0.6 and hard turns 3.0, adds a slight bias for cells on biome boundaries, and a small noise nudge (twist, not windiness: measured ~76–78% straight steps, ~0% hard turns).
- Rivers never cross themselves, never merge, never sit on water/mountain/dense forest, keep one cell of clearance from other rivers, and every system is a simple path — the "never a 4-way junction" rule holds by construction (degree cap ready for a future tributary pass).
- System count scales with map size (~2 on 24×18, up to 10, `riverCountForMap`), alternating wide/small; minimum length scales too (`minRiverLength`: 8 on 24×18 up to 40; measured 8–28 cells on small maps, 16–78 on large). **Measured shape (seeds 1–20):** 76–78% straight steps, 22–24% soft turns, <1% hard turns — twist without meander-spaghetti.
- **No resources, castles or settlements are placed on river cells**, and the hero spawn cell is force-cleared.
- Movement integration: `GameMap.isPassable`/`GameMap.cost` consult the river layer, so pathfinding, charters, AI movement and castle-placement reachability all respect rivers automatically.

## Resource tile placement

✅ **Implemented.** Resources are placed by per-terrain density — see [resources.md](./resources.md#biome-aware-density-matrix) for the full matrix. Water, impassable mountain and impassable dense forest are never assigned a resource; mountain-edge tiles get a spillover boost for stone/iron.

Implementation: [`src/map/resourceTiles.ts`](../src/map/resourceTiles.ts) (`placeResourceTiles`).

### Biome rules (summary)

| Resource   | Preferred biomes                          | Avoids        |
|------------|-------------------------------------------|---------------|
| Gold       | Grass, dirt (anywhere with foot traffic)  | Mountain, water |
| Wood       | **Forest** (high), grass (low)            | Desert, mountain, water, dense forest |
| Stone      | **Mountain** (high), dirt (low)           | Forest, water |
| Iron Ore   | **Mountain** (medium-high), dirt (low)    | Forest, water |
| Arcane Dust| **Desert** (high), dirt (low)             | Forest, mountain, water |

## Rendering

- **Hex outline:** 1px darker stroke.
- **Terrain fill:** flat colour from palette.
- **Decoration overlay:** trees on forest, wave ripples on water, sand hatch on desert, peak silhouette on mountain, murky pools + reeds on swamp, snow drifts on snow (procedural).
- **Resource overlay:** small icon in the hex centre for unclaimed resource tiles.
- **Settlement overlay:** town sprite on top of resource icon when claimed (procedural, owner-coloured).

Implementation: [`src/render/`](../src/render/).

## Data model

✅ **Implemented.** The map's authoritative state lives in a server-side table:

```sql
CREATE TABLE IF NOT EXISTS tiles (
  id          SERIAL PRIMARY KEY,
  game_id     INTEGER NOT NULL REFERENCES games(id) ON DELETE CASCADE,
  q           INTEGER NOT NULL,
  r           INTEGER NOT NULL,
  terrain     TEXT NOT NULL,
  resource    TEXT,
  UNIQUE (game_id, q, r)
);
CREATE INDEX IF NOT EXISTS tiles_game_idx ON tiles (game_id);
```

- `terrain` is non-null; `resource` is null for tiles without a deposit.
- `POST /api/games` generates the tile grid using `getOrCreateGameMap(seed, mapSize)` and bulk-inserts the rows via a single 5-parameter `UNNEST` query (`generateAndInsertTiles` in `server/routes.ts`). `GET /api/games/:name/tiles` returns them.
- Client-side `GameSessionManager.loadGame` reconstructs `GameMap` deterministically from `(seed, map_size)` via `getOrCreateGameMap` (eliminating the `/tiles` HTTP payload on game load while keeping `GameMap.fromTiles` and the `/tiles` endpoint available).

## Future: randomized per-game tiles

⏸️ **Deferred.** Documented for roadmap visibility.

The `tiles` table's contents are opaque to the client. Today every game with the same seed produces an identical grid. The server-side generator can be swapped later to:

- **Random per-game:** each new game rolls a fresh grid (no seed → no reproducibility), persisted to `tiles`.
- **Hand-authored levels:** designers place specific `(q, r)` terrain/resource rows by hand, ships as level JSON.
- **Procedural-but-biased:** change the biome density tables, change the noise function, or fold in per-game "events" (a continent shattered by volcanoes) without touching the client.

Because the client only reads the table, all of these are server-only changes. No `GameMap` API changes are needed when this lands.

## Camera

- Pan: drag with mouse.
- Zoom: mouse wheel, clamped to `0.25x – 3x`. Zoom anchors on cursor position.
- Initial position: centred on map centre (`(width-1)/2, (height-1)/2`).
- DPR-aware: `Camera.apply` includes device pixel ratio so coordinates stay correct on retina displays.

## Minimap

- Bottom-right corner, fixed CSS size (180 × ratio × height).
- Shows all tiles with terrain colours.
- Hero position: amber/red marker.
- Path: translucent overlay.
- ✅ Resource tiles: small amber dot indicator (per-resource tint optional).

## Fog of war

✅ **Implemented** (shipped long before the 2026-09-29 playtest pass; this section replaced a stale "deferred entirely" note). Visibility is computed per frame in [`src/render/fog.ts`](../src/render/fog.ts) as the union of:

- **Hero vision rings** — radius 4 (`VISION_RANGE`) around every hero's position.
- **Settlement vision rings** — radius `controlRange(level)` around every castle (grows with settlement level).

Non-visible hexes are covered with a semi-transparent fog overlay on the map and render black on the minimap. Resource deposits are hidden under fog too — the old "resource tiles stay always visible" v1 decision is superseded. Moving into fog is **allowed by design** (HoMM-style); path segments crossing fogged tiles draw brighter over a dark under-stroke so a planned move stays legible.

**Uncharted mode (2026-10-17).** Games created with the New Game "Uncharted mode" toggle (`lobby.uncharted`) replace the two-state fog with **three visibility tiers**, maintained per player: **visible** (current hero/settlement vision rings), **revealed** (explored earlier, now shaded under the translucent fog overlay), and **uncharted** (never explored by that seat — painted fully opaque black, so the map reads as a hole rather than fog). Each player's reveal is the persisted `Player.revealedTiles` list (`"q,r"` keys, seeded at game creation from the seat's starting vision and merged server-side on moves, charter travel, captures, and end of turn), accumulated client-side per session by `src/render/reveal.ts` and rendered as the `unchartedHex` scene node; without the option, games keep the original two-state fog.

**Unexplored tiles reveal no terrain info until seen** (locked decision, 2026-09-29 playtest fixes): the tile popup on a fogged tile shows coordinates + "Unexplored" only — `TileInfo.terrain` is null and the terrain/move-cost/deposit/settlement/heroes/charter/territory lines are all suppressed (`src/screens/adventure/tileInfo.ts`; the existing exception — tiles you own stay visible — is kept). Similarly, hover path previews (`AdventureView.updatePath()`) and click path/attack resolution (`resolveAdventureClick`) filter `occupiedHexes` and enemy targets through `computeVisionFromState` (`src/render/fog.ts`), so unseen fogged heroes never block path previews or leak an attack intent. The server-side `tiles` table still holds the full grid; the gate is a client presentation rule, not an information-model change.
